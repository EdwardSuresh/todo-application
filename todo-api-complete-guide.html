What you built, explained with 5Ws and a H

You built a REST API — a web service that lets any client (a browser, a mobile app, Postman, or another program) create, read, update, and delete todo items over HTTP. It is now live on the public internet via Render.

WHAT

A Todo CRUD API. CRUD = Create, Read, Update, Delete — the four basic operations on data. Your API exposes 5 endpoints under /todos that store todo items (title, description, priority, completed flag, end time) in a SQLite database file called todos.db.

WHY

To separate data from presentation. An API means any front end — a React website, an iPhone app, an Excel macro — can talk to the same data using plain HTTP + JSON. This is exactly how Shopify, Gmail, and banking apps work behind the scenes: the screen you see is just a client calling APIs like this one.

WHO

The layers each have a job. FastAPI is the receptionist (receives HTTP requests, routes them). Pydantic schemas are the security guard (validate incoming JSON). SQLAlchemy is the translator (turns Python objects into SQL). SQLite is the filing cabinet (stores the rows). Uvicorn is the building itself (the server that keeps the doors open).

WHEN

At every HTTP request. When a client calls POST /todos, the whole pipeline fires in milliseconds: validate → open DB session → insert row → commit → return JSON. Table creation happens once, at app startup (Base.metadata.create_all in main.py).

WHERE

Locally and on Render. On your laptop it runs at http://127.0.0.1:8000. In production, Render pulls your GitHub repo EdwardSuresh/todo-application, builds it, and serves it publicly at https://todo-application-tazt.onrender.com. The database file lives on the server's disk next to the code.

HOW

Layered architecture + dependency injection. Each request flows: Client → Uvicorn → FastAPI router → (Pydantic validates) → route function gets a DB session via Depends(get_db) → SQLAlchemy runs SQL → SQLite → response model serializes the result back to JSON.

🍽️ Real-world analogy — a restaurant: The customer (client) gives an order (HTTP request) to the waiter (FastAPI router). The waiter checks the order is valid — no ordering dishes not on the menu (Pydantic validation). The order goes to the kitchen (SQLAlchemy) which knows how to fetch ingredients from the pantry (SQLite). The finished dish comes back on a standard plate (JSON response shaped by TodoResponse). Uvicorn is the restaurant building: without it open, nobody gets served.

Architecture diagram

This is a classic 3-layer (n-tier) architecture: Presentation (API layer) → Business/Data-access layer (ORM) → Storage layer (database). The same pattern scales from this todo app up to enterprise banking platforms — only the boxes get bigger.

Line-by-line walkthrough

Read the files in this order — it follows the dependency chain: database.py → models.py → schemas.py → routes/todos.py → main.py. Each earlier file provides something the next one imports.

app/database.py DB plumbing — engine, sessions, Base, get_db()
#CodeWhat it does & why
1from sqlalchemy import create_engineImports the factory function that builds an Engine — SQLAlchemy's object that manages actual connections to the database.
2from sqlalchemy.orm import declarative_base, sessionmakerdeclarative_base makes the parent class your models inherit from; sessionmaker builds a factory for Session objects (a session = one unit of conversation with the DB).
4SQLALCHEMY_DATABASE_URL = "sqlite:///./todos.db"The connection string. Format: dialect:///path. sqlite:///./todos.db = "SQLite database, file todos.db in the current working directory." Swap this one string to postgresql://user:pass@host/db and the whole app moves to Postgres.
6–9engine = create_engine( SQLALCHEMY_DATABASE_URL, connect_args={"check_same_thread": False}, )Creates the engine. check_same_thread=False is a SQLite-only flag: SQLite normally forbids using one connection from multiple threads, but FastAPI may handle each request on a different thread, so we relax that check. (Sessions still keep access safe per-request.)
10SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)A session factory. Calling SessionLocal() yields a fresh session bound to our engine. autocommit=False: nothing is saved until you explicitly call db.commit() — you control transactions. autoflush=False: SQL isn't sent mid-query behind your back.
11Base = declarative_base()The registry/parent class. Every class inheriting from Base (like TodoModel) is registered, so later Base.metadata.create_all() knows which tables to create.
14–19def get_db(): db = SessionLocal() try: yield db finally: db.close()The dependency used by every route via Depends(get_db). It's a generator: it opens a session, yields it to the route function (the route runs at the yield point), and the finally block guarantees the session closes afterwards — even if the route raised an exception. Real-world analogy: a library checkout desk — you borrow a book (session), and no matter what happens, it gets returned.
app/models.py ORM model — the "todos" table as a Python class
#CodeWhat it does & why
1from sqlalchemy import Boolean, Column, Integer, StringColumn type building blocks — each maps a Python type to a SQL column type (Integer→INTEGER, String→VARCHAR/TEXT, Boolean→BOOLEAN).
2from .database import BaseRelative import (. = same package). Inheriting from this Base is what registers the table.
4class TodoModel(Base):One class = one table. Instances of this class = rows.
5 __tablename__ = "todos"The actual table name in SQLite. Without this SQLAlchemy raises an error.
7 id = Column(Integer, primary_key=True, index=True)Primary key: unique identity of each row. For an integer PK, SQLite auto-increments it — that's why create_todo never sets id; the DB assigns it. index=True builds an index for fast lookup.
8 title = Column(String, index=True)Text column; indexed so searches by title stay fast as the table grows.
9 description = Column(String, index=True)Text column for details. (Indexing long free-text is rarely useful — safe to drop index=True here.)
10 priority = Column(Integer, default=1)Numeric priority; if a row is inserted without one, the DB stores 1.
11 completed = Column(Boolean, default=False)Done flag; new todos start as not-completed.
12 end_time = Column(String, default=None)Due date stored as a plain string (nullable). Improvement idea: use DateTime so the DB can sort/filter by date properly.
app/schemas.py Pydantic schemas — API input/output contracts
#CodeWhat it does & why
1from pydantic import BaseModelPydantic's base class gives automatic parsing + validation + JSON serialization to any class that inherits it.
3–8class TodoCreateOrUpdate(BaseModel): title: str description: str completed: bool = False priority: int = 1 end_time: str = NoneThe request body contract for POST and PUT. Fields with no default (title, description) are required — if a client omits them or sends the wrong type (e.g. "priority": "high"), FastAPI automatically replies 422 Unprocessable Entity with a precise error, before your code even runs. Fields with defaults are optional. Note there is no id here — clients never choose IDs; the database does.
10–17class TodoResponse(BaseModel): id: int title: str description: str completed: bool priority: int end_time: str = NoneThe response contract: what every endpoint returns. It does include id because responses describe rows that already exist. Acting as response_model, it also filters output — if you later add a secret column, it won't leak unless you add it here.
19–20 class Config: from_attributes = TrueNormally Pydantic reads dicts. This flag lets it read object attributes too — so FastAPI can convert a SQLAlchemy TodoModel row directly into a TodoResponse (reading todo.id, todo.title, …). Without it, returning ORM objects fails.
app/routes/todos.py The 5 CRUD endpoints
#CodeWhat it does & why
1–2from fastapi import APIRouter, Depends, HTTPException from sqlalchemy.orm import SessionAPIRouter = a mini-app of grouped endpoints; Depends = dependency injection marker; HTTPException = the proper way to return HTTP errors; Session = type hint for the DB session.
4–6from ..database import get_db from ..models import TodoModel from ..schemas import TodoCreateOrUpdate, TodoResponse.. means "go up one package level" (from routes/ up to app/) then import. Pulls in the session dependency, the table class, and the two contracts.
8router = APIRouter(prefix="/todos", tags=["todos"])Every route below is automatically mounted under /todos, and grouped under a "todos" heading in Swagger UI. Central place to change the URL base.
10–13@router.get("", response_model=list[TodoResponse]) def get_todos(db: Session = Depends(get_db)): todos = db.query(TodoModel).all() return todosREAD (all). The decorator maps GET /todos to this function. Depends(get_db) tells FastAPI: before running this, call get_db() and hand me the session. db.query(TodoModel).all() runs SELECT * FROM todos and returns a list of TodoModel objects; response_model=list[TodoResponse] converts each into clean JSON.
15–20@router.get("/{todo_id}", response_model=TodoResponse) def get_todo(todo_id: int, db: Session = Depends(get_db)): todo = db.query(TodoModel).filter(TodoModel.id == todo_id).first() if not todo: raise HTTPException(status_code=404, detail="Todo not found") return todoREAD (one). {todo_id} in the path becomes the function argument — and because it's typed int, FastAPI converts and validates it ("abc" → automatic 422). .filter(...).first() = SELECT … WHERE id = ? LIMIT 1; returns None if absent, in which case we raise a proper 404 instead of crashing.
22–28@router.post("", response_model=TodoResponse) def create_todo(todo: TodoCreateOrUpdate, db: Session = Depends(get_db)): new_todo = TodoModel(**todo.dict()) db.add(new_todo) db.commit() db.refresh(new_todo) return new_todoCREATE. Because todo is typed as a Pydantic model, FastAPI reads the JSON body and validates it. **todo.dict() unpacks the validated fields into keyword arguments — same as TodoModel(title=…, description=…, …). db.add stages the row; db.commit() writes it (INSERT); db.refresh reloads the row from the DB so new_todo.id now holds the auto-generated ID we return to the client. (Pydantic v2 tip: todo.model_dump() is the modern name for .dict().)
30–41@router.put("/{todo_id}", response_model=TodoResponse) def update_todo(todo_id: int, todo: TodoCreateOrUpdate, db: Session = Depends(get_db)): existing_todo = db.query(TodoModel).filter(TodoModel.id == todo_id).first() if not existing_todo: raise HTTPException(status_code=404, detail="Todo not found") for key, value in todo.dict().items(): setattr(existing_todo, key, value) db.commit() db.refresh(existing_todo) return existing_todoUPDATE. Fetch → 404 if missing → loop over the validated fields and copy each onto the existing object with setattr (dynamic version of existing_todo.title = value). SQLAlchemy tracks these changes ("dirty" state), and commit() issues the UPDATE statement. PUT semantics = full replacement: the client sends all fields every time.
43–51@router.delete("/{todo_id}", response_model=TodoResponse) def delete_todo(todo_id: int, db: Session = Depends(get_db)): todo = db.query(TodoModel).filter(TodoModel.id == todo_id).first() if not todo: raise HTTPException(status_code=404, detail="Todo not found") db.delete(todo) db.commit() return todoDELETE. Same fetch-or-404 pattern, then db.delete + commit() runs the DELETE statement. Returning the deleted object is a friendly touch — the client sees exactly what was removed (handy for "undo" features).

Libraries used (from requirements.txt)

Core — your code imports these directly

  • fastapi (0.141.1) — The web framework. Turns Python functions into HTTP endpoints via decorators, performs automatic validation from type hints, and auto-generates interactive docs at /docs (Swagger UI) and /redoc. Real-world example: it's the "waiter" — takes orders, checks them, delivers plates.
  • SQLAlchemy (2.0.52) — The ORM (Object-Relational Mapper). Lets you work with Python classes/objects (TodoModel) instead of writing raw SQL strings; it generates the SELECT/INSERT/UPDATE/DELETE for you and manages connections and transactions. Also protects against SQL injection by parameterizing queries.
  • pydantic (2.13.4) — Data validation using Python type hints. Powers your schemas.py: parses incoming JSON, enforces types, applies defaults, and rejects bad input with clear 422 errors. Example: sending "completed": "banana" is stopped at the door.
  • uvicorn (0.52.4) — The ASGI web server that actually listens on a port and speaks HTTP. FastAPI is just an application; Uvicorn is the engine that runs it, both on your laptop and on Render.

Supporting — installed automatically as dependencies

  • starlette (1.6.0) — The ASGI toolkit FastAPI is built on top of; supplies routing, requests/responses, and middleware machinery.
  • pydantic_core (2.46.4) — Pydantic's high-speed validation engine, written in Rust. This is why Pydantic v2 validation is so fast.
  • anyio (4.14.2) — Async concurrency layer Starlette uses; it also runs your plain def route functions in a threadpool so they don't block the event loop.
  • h11 (0.16.0) — Pure-Python HTTP/1.1 protocol implementation used by Uvicorn to parse and emit HTTP messages.
  • click (8.4.2) — Command-line interface toolkit; provides the uvicorn … command's argument parsing.
  • greenlet (3.5.5) — Lightweight coroutine support SQLAlchemy uses internally, especially for its async features.
  • typing_extensions / typing-inspection / annotated-types / annotated-doc / idna / colorama — Small utilities: newer typing features on older Pythons, type inspection for Pydantic, constraint types, domain-name handling, and colored terminal output on Windows.

⚠️ Present but unused — safe to remove

  • Flask (3.1.3), Flask-SQLAlchemy, Jinja2, Werkzeug, itsdangerous, blinker, MarkupSafe — This is the entire Flask web-framework family, a competitor to FastAPI. Nothing in your code imports Flask, so these were likely left over from experimentation. Removing them makes Render builds faster and the dependency surface smaller. Portfolio-rationalization instinct applies to requirements files too: every unused dependency is cost and attack surface.
Cleaned-up requirements.txt for this app really only needs four top-level lines — fastapi, uvicorn, SQLAlchemy, pydantic — pip resolves the rest automatically.

Deployment pipeline at a glance

Two free-tier realities to know

1 · Cold starts. The banner in your dashboard says it plainly: free instances spin down after ~15 minutes of no traffic, and the next request waits 50+ seconds while the container restarts. Fine for demos; upgrade to a paid instance for always-on behavior.
2 · Ephemeral disk = your SQLite data disappears. The free filesystem is rebuilt on every deploy and restart, so todos.db resets to empty. Any todos created through the live site vanish on the next push or spin-down. Fixes, in order of seriousness: (a) accept it for a demo; (b) attach a paid Render Persistent Disk; (c) the production answer — swap the connection string in database.py to a managed PostgreSQL database (Render offers one) and change nothing else in your code. That one-line swap is the payoff of the layered architecture in Tab 2.
